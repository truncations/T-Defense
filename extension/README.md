# T-Defense Page Guard v0.4.1

1. Keep the local Python backend running at http://127.0.0.1:8000. Load this folder in Chrome/Edge Developer mode -> Load unpacked. When updating, keep the same loaded folder, click Reload and refresh existing website tabs.
2. Copy the pairing code from local setup into the toolbar popup. This is not your VirusTotal API key. Browser/backend restarts may require pairing again; provider keys remain server-side.
3. Click Start everywhere and grant the optional HTTP/HTTPS website access once. Monitoring follows current/new supported pages until Stop everywhere, with preference saved across browser restarts. Protected browser pages/frames remain unsupported and timer throttling can delay background checks. The backend must be running.
4. The compact dock starts bottom-right below top profile controls. Click ! to review all numbered highlights/list entries. Drag the handle or use arrow keys to move it; The saved position applies across sites and tabs in this browser profile, including already-open monitors; toolbar Reset panel position restores the default everywhere. ! is centered and pulsing respects reduced motion. Routine checks do not rebuild unchanged findings or alternate the visible footer. Check details holds diagnostic IDs/times.
5. Closing/hiding a message or navigating to another view clears its rows/markers automatically. Check again establishes a fresh current review. Uninspected current or incomplete reputation evidence stays explicitly unresolved, never safe.
6. To trust exact content: select its finding, open the genuine toolbar popup, Preview selected element for trust, then Trust this exact content. A link inside a message scopes to that whole message. Whole-page warnings and oversized identities are ineligible. No automatic clean-result whitelist exists. The native local IndexedDB stores only a scoped SHA256 hash, origin, kind and timestamp; no raw text, typed values or full URLs. Unchanged signatures skip backend detection; metadata is still read locally to detect changes. Changes to text/destinations/form metadata trigger checking. Remote script/file/image bytes are not verified by a saved HTML signature. Trust is your decision, not certification. HTTP pages without secure crypto cannot create trust entries.
7. Manage local trusted elements -> Revoke, or Clear all trust decisions. Entries persist in this extension profile until revoked/cleared/profile removal. Keep the same extension folder/ID while updating. Capacity5000 rejects additions rather than evicting existing decisions. Revocation invalidates pending bypasses immediately.

Local rules cover reward/account bait, crypto multipliers, pressure/secrecy/payment demands, untrusted software, form/link clues and possible promotional spam. Image-heavy email is a content-coverage caution; no OCR or medical authenticity analysis is performed. Supported Gmail Spam-folder cues are local URL/visible-message metadata, not account API access. False positives and misses remain possible.

VirusTotal remains optional per monitored tab/origin. Strong local risks do not trigger provider requests; otherwise it is fallback domain reputation, not exact URL verification. Public hostnames queried are shared with VirusTotal and added to its community dataset. Avoid confidential hostnames. The backend key belongs only in ignored .env/environment. Existing4/minute500/day budgets, cache and unknown/failure handling apply. New sites do not inherit opt-in. No raw page text, typed values, HTML/cookies/full links go to Python or VirusTotal.

Use /extension-lab for synthetic local examples. All example links/submissions are independently canceled by the lab, including after an override. No real Gmail/Discord account is accessed by tests; automated permission tests use a documented temporary manifest with pregranted host access. Production requests optional access through your actual toolbar click.

Version0.4.1 keeps a confirmed backend outage visible during automatic/manual retries until a successful current check. A transient network/timeout/server failure gets one retry after600ms; authentication errors remain immediate. This avoids false recovery flicker without hiding a continuing outage. Conversation-level analysis is not part of this update.
